# 空间索引性能测试报告：KD-Tree vs Octree vs Brute-Force
**报告版本**：v1.0  
**测试日期**：2026-06-04  
**测试环境**：Release 编译 | CPU 本机实测 | Windows 10 x64 | Visual Studio 2026  
**测试对象**：3种点云分布 × 2类查询操作（K-NN 近邻、Radius 范围）

---

## 一、测试说明
1. **点云分布类型**
   - 均匀分布：点在空间中随机均匀散布，无明显聚集
   - 聚簇分布：点集中在若干个空间区域，形成团簇状
   - 稀疏分布：点在大空间中极少量散布，多数区域无点
2. **对比算法**
   - Brute-Force（暴力）：遍历所有点计算距离，无索引
   - KD-Tree：基于坐标轴分割的二叉空间索引树
   - Octree：基于八叉空间分割的多层次索引结构
3. **统计指标**：单次查询平均耗时（单位：ms），每组测试重复1000次取均值
4. **查询参数**
   - K-NN：固定 K=10（查询最近10个邻居）
   - Radius：固定半径 r=0.1（查询指定半径内所有点）

---

## 二、K 近邻（K-NN）查询性能测试

### 2.1 均匀分布点云
| 算法 | 单次查询耗时(ms) | 性能对比 |
| :--- | :--- | :--- |
| KD-Tree | 0.003 | 最优 |
| Octree | 0.058 | 比 KD-Tree 慢 18.3 倍 |
| Brute-Force | 0.070 | 比 KD-Tree 慢 22.3 倍 |

**结论**：均匀数据下 KD-Tree 剪枝效率最高，暴力法因无索引遍历全量点耗时最长。

### 2.2 聚簇分布点云
| 算法 | 单次查询耗时(ms) | 性能对比 |
| :--- | :--- | :--- |
| Brute-Force | 0.066 | 最优 |
| KD-Tree | 0.067 | 比暴力慢 1.5% |
| Octree | 0.118 | 比暴力慢 78.8% |

**结论**：聚簇场景下暴力法与 KD-Tree 性能接近，Octree 因大量空格子遍历导致性能下降。

### 2.3 稀疏分布点云
| 算法 | 单次查询耗时(ms) | 性能对比 |
| :--- | :--- | :--- |
| KD-Tree | ≈0.000 | 最优 |
| Brute-Force | ≈0.000 | 持平 |
| Octree | 0.016 | 额外开销 |

**结论**：稀疏场景数据量极少，索引优势不明显，Octree 因树结构维护有小幅额外开销。

## 四、综合分析与选型建议

### 4.1 算法性能总结
| 场景 | 最优算法 | 次优算法 | 不推荐算法 |
| :--- | :--- | :--- | :--- |
| 均匀 K-NN | KD-Tree | Octree | Brute-Force |
| 聚簇 K-NN | Brute-Force/KD-Tree | - | Octree |
| 稀疏 K-NN | KD-Tree/Brute-Force | - | Octree |
| 均匀 Radius | KD-Tree/Octree | - | Brute-Force |
| 聚簇 Radius | KD-Tree/Octree | - | Brute-Force |
| 稀疏 Radius | KD-Tree/Brute-Force | - | Octree |

### 4.2 工程落地建议
1. **静态点云 + 高频 K-NN 查询**：优先选择 **KD-Tree**，综合性能最优
2. **动态点云 + 大范围空间查询**：选择 **Octree**，空间划分更灵活，动态更新效率更高
3. **聚簇数据 K-NN 查询**：暴力法与 KD-Tree 性能接近，可根据点云规模选择
4. **所有场景 Radius 查询**：KD-Tree 与 Octree 均大幅优于暴力法，优先使用空间索引

### 4.3 注意事项
- 耗时显示为 **≈0.000ms** 表示单次运行耗时低于系统时钟最小统计精度（通常为 0.001ms），实际耗时趋近于0
- 索引构建时间未计入本次测试（仅统计查询阶段耗时），动态点云场景需额外评估索引更新成本
- 测试结果基于固定参数（K=10、r=0.1），实际应用中需根据具体参数调整选型
